# SupplyPilot V2 — 前端、查詢、顯示及明確不新增功能

> 對應：[#143 Kanban UI](https://github.com/liujiawei-tw/supplypilot/issues/143)、[#144 PO 搜尋](https://github.com/liujiawei-tw/supplypilot/issues/144)、[#148 共用格式](https://github.com/liujiawei-tw/supplypilot/issues/148)、既有 [#126 AI 排版](https://github.com/liujiawei-tw/supplypilot/issues/126)。

## 1. 介面語言／顯示契約

| 類型 | 已確認格式或原則 |
|---|---|
| 介面 | zh-TW 繁體中文 |
| 時區 | Asia/Taipei（UTC+8）用於需要本地顯示的日期時間 |
| Date | YYYY/MM/DD |
| DateTime | YYYY/MM/DD HH:mm |
| 數字 | 千分位，如 1,250 |
| 數量 | 顯示原單位與數值，如 1,250 KG；精度依物料/交易原有規格 |
| 金額 | 保留資料所屬原幣別（如 TWD、USD），不得隨意匯率轉換 |
| AI 回答金額 | **最多 2 位小數**，去除多餘尾隨零；15,000.0000 → 15,000、100.5000 → 100.5、100.5678 → 100.57 |

- AI 答案顯示與一般表格的金額格式可以是不同 UI 情境，但應共用幣別/千分位規則。一般金額兩位固定顯示示例 TWD 125,000.00；AI 回答遵守不顯示多餘尾零。
- **所有格式化只在顯示層**，不得在 MySQL、DTO、BigDecimal 計算或比較時先四捨五入。
- 保留完整幣別，不自行擴充 V1 的多幣別付款或換匯功能。
- 既有 #126 尚須改善 AI 回答摘要/各 PO 分行/來源排版，不能混淆格式美化與 [#127](https://github.com/liujiawei-tw/supplypilot/issues/127) 的 AI 比較條件正確性。

## 2. 看板與列表同一入口

- 使用 /purchase-orders，同頁切換 **看板／列表**。桌面預設八階段 Kanban。
- 看板卡片對應真實 PO，後端決定狀態、逾期與可操作動作；拖曳跨業務階段需要明確確認與後端成功回應。
- 列表保留狀態、日期範圍、逾期、排序、分頁，再加入採購單編號、供應商代碼/名稱、物料代碼搜尋。
- 篩選須由 Backend 完成後分頁，不能只搜尋前端當前表格頁。
- 同頁切換與多條件查詢不得造成丟失未提交的表單資料，或錯把看板 Stage 當 PO 交易狀態。

## 3. RWD

- 桌面優先：提供完整操作、Kanban 拖曳、PO 編輯、收貨及文件管理。
- 手機版：支援基本採購單／庫存／供應商資料查詢與 AI 問答，不要求完整 Kanban 拖曳與所有複雜表單操作。
- 平板／窄視窗按實際寬度調整，不因隱藏按鈕而製造權限提升；不可用的手機複雜操作需明確提示。
- 鍵盤、縮放 200% 與 Loading／Empty／Error／Success 邊界仍須回歸測試。

## 4. 已確認維持現狀的功能

| 項目 | V2 |
|---|---|
| 庫存管理 | 維持現有 Stock Levels、Stock Transactions、手動調整與既有權限；**不新增安全庫存狀態警示／低於安全庫存篩選** |
| Dashboard | 既有角色工作台／待辦與採購單逾期 Badge 保留；V2 帳號角色簡化後對應調整 |
| 通知 | **不做**站內通知中心、Email、LINE 或排程推播 |
| PO 匯出 | **不做** CSV、XLSX、PDF |
| PO 文件 | 文件與採購單管理維持獨立；**不做**關聯附件與附件 AI 自動分析 |
| 供應商評分 | 現有兩項人工分數保留；不做歷史評鑑、排名 |
| 個人偏好 | 不新增使用者自訂語言／時區／數字格式 |

## 5. 主要驗收

1. 在繁體中文、台灣日期時區下，金額、數量、單位與原幣別正確；表格與 AI 的數字值未改變 DB/BigDecimal。
2. 同頁看板與列表正確切換，手機至少能瀏覽列表與 AI 查詢；桌面完整操作。
3. 只套現有授權的後端 API；逾期狀態由 Backend 權威計算。
4. 不因 V2 專題增加明確排除的通知、匯出、附件、庫存警示功能。
