# SupplyPilot 採購工作介面改版決策

## 設計任務

讓採購人員在同一個工作脈絡中找到採購單、看懂八階段進度與兩種交期，並安全完成有權限的下一步；需要核對文件或 AI 回答時能回到真實來源。產品操作模式為 Operate。依使用者明確授權自行選定方向，未等待設計稿選擇。

## 三種資訊架構方向

| 方向 | 組織與工作方式 | 優點 | 取捨 |
|---|---|---|---|
| 搜尋優先的資源查找台 | 先選 PO、供應商、物料或文件範圍，輸入查詢後看對應結果 | 找資料快；同一入口連接不同主檔 | 目前文件 API 沒有自由文字標題搜尋，各端點支援的查詢條件和權限不同，不能做成一個假裝完整的全域索引 |
| 八階段採購單工作台（採用） | 採購單作為主工作面；Kanban／列表同頁切換，搜尋與篩選作用於明確範圍，選取 PO 後就近查看欄位和受控操作 | 直接吻合已實作 V2 流程；比較多張 PO 時能同時看 Stage、正式狀態、兩種交期；不需新增 API | PO 細節內容多，需適度分層；手機版以列表和單筆全螢幕明細取代桌面看板 |
| 每日處理佇列 | 以待核准、待下單、待驗收、待付款的任務分組，完成後回佇列 | 清楚凸顯下一步；可減少管理者尋找待處理工作 | 容易把既有 Stage 重新包裝成待辦或通知；可能需要額外分類與排序契約，且不能完整表達所有採購情境 |

## 方向評估

| 方向 | 日常效率 | 資料核對 | 多筆 PO 閱讀 | 操作錯誤風險 | AI／來源 | 手機／平板 | 維護成本 |
|---|---|---|---|---|---|---|---|
| 搜尋優先的資源查找台 | 高 | 中高 | 低 | 中 | 中高 | 高 | 中；需串接多個不同權限、篩選與分頁的 API |
| 八階段採購單工作台 | 高 | 高 | 高 | 低 | 中高 | 中高；手機改為列表 | 低；沿用現有 V2 看板、列表、Detail 與 API |
| 每日處理佇列 | 高 | 中 | 中 | 中；佇列分類可能被誤認為正式狀態 | 中 | 高 | 中高；需要額外佇列分類、排序與例外處理 |

採用 PO 工作台作為產品主軸；資源查找以現有 API 能力作為快捷入口；不新增獨立待辦流程。依 V2 確認的契約保留同頁八階段 Kanban／列表切換和受控 Backend 命令。

## 視覺與互動決策

- 以現代物流導引為視覺線索：深海軍藍建立工作框架，冷調石板灰與白色承載內容，青綠標示主要動作與目前工作路徑，琥珀色僅提醒交期或需要注意的狀態。
- 使用系統繁中字體與等寬數字；以清晰欄位、層級及分隔線組織資料，各頁依任務採用不同布局，不把全站做成同一種卡片與表格模板。
- 以精簡頂部導覽取代固定左側 Sidebar。主路徑是採購單、收貨、供應商、物料、庫存、文件、AI；人員管理只依既有獨立授權呈現。
- 搜尋按資源範圍呼叫既有 API。供應商與物料命中代碼或名稱後，完整清單保留原命中欄位與伺服器分頁；庫存使用物料代碼條件。文件使用類型、供應商及狀態篩選，不提供不存在的文字搜尋。不要查詢尚未載入的本機資料冒充伺服器結果。
- PO 頁保留 Kanban／列表切換、篩選及分頁。桌面側欄／抽屜承載選取明細；手機用可搜尋列表和全螢幕明細。
- 八階段軌只呈現目前後端 Stage；操作後重新查詢再更新。交期雙欄分別標示公司期望日與供應商承諾日。
- 重要提交明示將執行的後端命令；409 與寫入結果未知時，提供重讀及人工確認路徑，不自動重送。
- 文件索引、處理、審核狀態各自呈現。AI 來源顯示文件、版本與原文摘錄；不足時顯示證據不足。
- 手機以 PO、庫存、供應商查詢和 AI 問答為主；無拖曳、滑出即提交或小型觸控目標。

## 2026-10-26 視覺精修：現代、克制、低 AI 感

使用者補充要求全站調整為現代風格，並明確表示不要過重的 AI 視覺。UI/UX Pro Max 的採購工作流設計系統搜尋指向 Minimalism & Swiss Style，密集資料檢視另以 Data-Dense Dashboard 作為參考；配色建議經 SupplyPilot 色彩對比及工作情境調整為海軍藍、青綠和有限的交期琥珀色。AI 仍是有權限者可呼叫的工具，不是整個產品的品牌主視覺。

Impeccable `concept-seed` 方向種子（key `0659204b`）包含植物生命週期圖譜及機場導引標示等候選。植物圖譜的自然／季節語意與採購交接缺乏直接關聯；導引標示的「目前位置與下一站」能轉譯為已核實的 PO Stage 與受控下一步，因此採用其導引層級與路徑提示紀律，導覽仍沿用使用者熟悉的標準網頁控制項。依使用者已授權自行選擇的指示，沒有等待設計稿選擇。

- 不使用紫粉漸層、發光、玻璃擬態、機器人裝飾、空泛 KPI 圖表或沒有資料來源的指標。
- 深色頂部工具列、白色導覽、淺灰工作區與高可讀性資料列構成全站骨架；頁面依採購單、收貨、文件、主檔、匯入和授權狀態各自安排資訊。
- 保留 PO 身分與八階段狀態軌這個產品特徵；它只描述後端最新 Stage，不畫出未回傳的歷史，也不取代正式 PO status。
- 將原紫色生成式 favicon 換成與應用程式標記一致的階段路徑符號，標題、語系與瀏覽器主題色同步使用繁體中文及新外殼色彩。

## 實作範圍與設計檢查

- 共用工作框架改為精簡頂部導覽與明確內容區；路由頁面使用單一主要內容地標。資源搜尋先選類別與查詢，再呼叫對應既有 API，空查詢不顯示「無結果」。
- 採購單頁保留 Kanban／列表與現有篩選、分頁及命令；選取紀錄後就近顯示唯讀檢視。手機寬度切換為列表，避免窄螢幕保留桌面看板。另將交接單標籤本地化。
- 收貨頁改成驗收工作佇列及單筆交接檢視，沿用原有角色權限、整筆收貨操作與未知結果重新查詢路徑；明細保持唯讀，不新增價格或審批稽核資料。
- 文件與 AI 頁面將索引／處理狀態和回答來源分層呈現；供應商、物料、庫存及人員頁沿用既有 API 和授權契約整理搜尋與資訊層次。
- 獨立 UX 評閱指出 QuickFinder 初次載入容易被誤認為搜尋空結果、行動版搜尋按鈕缺少易讀名稱、巢狀主要地標，以及窄版 PO 看板。修正後加入搜尋狀態、按鈕名稱和圖示隱藏語意、移除巢狀 `<main>`，並使手機版使用列表。
- Impeccable detector 的保存結果涵蓋 PO 頁及交接單：兩個粗色邊線警示已改成中性色細線。Receiving 四個頁面檔案另執行 detector，回傳 `[]`；該次原始輸出沒有另存。這不是全站 detector 掃描。

## 風險與驗證範圍

風險是資訊密度變高時桌面 200% 縮放與繁體中文標籤會擠壓版面，以及多頁面共用 Shell 造成焦點或授權入口回歸。驗證細節、失敗分診與尚未執行項目見 [驗證紀錄](evidence/ui-ux-redesign/validation-summary.md)。沒有真實 Gemini／RAG／正式資料 E2E 時不宣稱通過。
